# コンシェルジュをコントロールプレーンとして作り直す

Status: 設計確定(2026-11-13 オーナーとの grill、Q1–Q31)。実装前
Decision: [ADR-0028](../decisions/0028-concierge-control-plane.md)

## 何を直すのか

コンシェルジュは Project の workspace の後から足したため、オーナーが使うと次の問題が起きていた。

| 症状 | 原因(2026-11-13 時点のコード) |
|---|---|
| コンシェルジュが開いたファイルを見る場所がない | コンシェルジュ画面にエディタがなく、`openFile` は `leaveConcierge()` で Project 画面へ移ってから開く |
| コンシェルジュに頼んで起動した agent が動いているのが見えない | タイルが画面の文字を読めるのは、この起動でその pane を一度表示したときだけ。起動直後の子はまだ表示されていないので空になる |
| チャット欄が狭い | チャットの幅が 460 で固定 |
| 看板の工程が各列で止まる | Clair は TODO の `stage` を表示するだけで、遷移のルールはコンシェルジュのプロンプトか skill に任せていた(ADR-0020)。`~/.clair/concierge` にその skill がなく、誰も `stage` を進めていなかった |
| 看板が操作できない、agent と TODO が分かれていて見づらい | カードは TODO の front matter から作る読み取り専用の表示で、agent のタイルはカードとは別の領域に並ぶ |

この計画では、コンシェルジュ画面を「すべての Project の仕事を管理する場所(コントロールプレーン)」とし、
Project の workspace を「実際に編集・実行する場所(データプレーン)」とする。

## 画面

コンシェルジュ画面を Clair の入口にする。Project の workspace は、カードや agent から
ターミナルを触る・ファイルを編集するときに移る詳細画面になる。

```
┌──────────────────────────────────────────────────────────────── [◉ ⌨︎] ┐
│ 会話タブ  │ Inbox │ Plan │ Impl │ Review │ Done  →(横スクロール)│ editor tabs │
│           │ ┌───┐ │┌───┐│┌───┐ │ ┌───┐  │ ┌───┐               │             │
│  チャット │ │本文│ ││画面││ │画面│ │ │画面│  │ │結果│               │  ファイル   │
│           │ └───┘ │└───┘│└───┘ │ └───┘  │ └───┘               │             │
│ composer  │ その他のエージェント(手動起動の agent の帯)          │             │
└──────────────────────────────────────────────────────────────────────┘
   ↕ドラッグ         ↕ドラッグ                                    ↕ドラッグ
```

- 3列(`チャット | 看板 | エディタ`)。境界はドラッグで動かし、幅を保存する。チャットは畳める。
  エディタ列は何かを開いたときだけ現れ、閉じると看板が広がる。会話タブはチャット列の上に残す。
- エディタ列はエディタのタブだけを持つ。どの Project のファイルも開いて編集でき、言語機能はそのファイルの
  Project のものを使う。Project 側で同じファイルを開いていれば、バッファを共有する。エクスプローラー・
  変更一覧・diff は持たない(diff は PR か Project 画面の既存のレビュー画面で見る)。
  コンシェルジュと子の `clair open` / `file.open` は、コンシェルジュ画面にいる間はこの列に開く。
- titlebar の右端に、コンシェルジュと IDE(Project の workspace)の切り替えボタンを置く。
  2つのアイコンの上をガラスの丸が滑る形(幅約 60pt)で、IDE 表示中に「あなた待ち」のカードがあれば
  コンシェルジュ側に点を出す。macOS 26 以上では `glassEffect` の morph、それ未満では
  `matchedGeometryEffect` で同じ動きを近似する。クラシック素材ではガラスの代わりに `surfaceActive` の塗りが滑る。
  視差効果を減らす設定では瞬時に切り替える。⌃⌘0 でも切り替える。
- activity bar のコンシェルジュアイコン、設定 `startConcierge`、サイドバーの TODO パネルと activity bar の
  TODO アイコン、今の「agent pane のタイル」の領域は削除する。
- 起動時は常にコンシェルジュ画面を開く。

## 看板

### 列と遷移

| 列 | 移したときに起きること |
|---|---|
| Inbox | 何も起きない。仕事を溜める場所 |
| Plan | plan 用の agent が起動し、`plan.md` を書く |
| Impl | impl 用の agent が起動し、worktree で実装する |
| Review | review 用の agent が起動し、自己検証と diff の要約を `review.md` に書く。冒頭に検索用の「要約」節を置く |
| Done | 後片付けをする(下記) |

- 列を移すのは人。agent が終わってもカードはその列に留まり、人が次へ移すのを待つ。
  自動で次の列へ進めるループは作らない(トークン消費を抑えるため)。
- 列を移すたびに新しい agent を起動する。前の工程の agent の会話は引き継がず、工程間の受け渡しは
  `plan.md`・`review.md`・diff だけにする。Review から Impl への差し戻しも、`review.md` を渡して新しく起動する。
- 実行中のカードを別の列へ移すときは、「実行中の agent を終了して移しますか」と確認してから終了する。
  入力待ち・完了・失敗のカードは確認なしで移す。
- どこからどこへでも移せる(逆方向を含む)。
- PR の作成(push を伴う)は列に結び付けず、Review のカードのボタンで人が押す。押すと PR を作る子が起動する。

### カード

- 実体は今の TODO ファイル(`~/.clair/todo/*.md`)。名前は todo のまま(`clair todo …`、`clair-todo` skill、
  `~/.clair/todo/`)で、画面上の呼び方だけ「カード」にする。
- `stage` の無い TODO はすべて Inbox に出す。Inbox の並びは今の TODO と同じく優先度→期限。
  既存の `stage` は `submit` / `check-A` / `check-B` / `review` を Review として読み、`lane` は無視する。
  ファイルは書き換えず、次に移したときに新しい値で上書きする。
- すべてのカードに、担当 agent の画面の末尾(約 14 行、1 秒ごと、色なし)をライブで出す。Inbox のカードは
  本文の冒頭を出す。列が入りきらなければ看板を横にスクロールする。カードをクリックすると本物の
  ターミナルをクイックルックで重ねる(今のタイルと同じ)。
  まだ一度も表示していない pane の画面は、daemon の terminal journal を GUI 側の headless VT
  (`ClairGhosttyVT`)に流して読む。
- 状態: 実行中 / 入力待ち(承認や質問) / 完了 / 失敗。完了と失敗は、列の agent が最後に
  `clair todo update path=… result=ok|failed note="…"` で報告する。プロセスの異常終了も失敗にする。
  報告がないまま `done` になったものは「完了(結果未報告)」と出す。`retry` は回数の表示だけ残し、
  上限超過の状態は削除する。
- 「あなた待ちだけ」と Project の絞り込みは残す。
- 看板に検索欄を置く。対象はタイトル・本文・`plan.md`・`review.md`(要約節を含む)・各工程の `note`・
  branch・PR URL で、過去の完了カードも含める。

### Done

- Done に移すと、そのカードの pane を閉じ、worktree と branch を消す。worktree に未コミットか
  未 push の変更があれば、止めて確認を出す。
- Done 列には完了から 7 日以内のカードだけを出す(日数は設定)。古いものはファイルを残したまま、
  列の末尾の「過去の完了 N 件」から見る。

### 対象 Project

- カードの `project` が無いまま Plan / Impl / Review に移すと、Project をパレットで選ばせる
  (最近使った順)。選んだ値をカードに記録してから起動する。
- パレットの先頭に「Project なし」を置く。選ぶと作業フォルダ(設定、既定 `~/Projects`)で起動する。
- Impl は常に worktree(`branch=`)で起動する。「Project なし」のカードは worktree を作らない。

### 列の skill

- Clair は既定の `clair-plan` / `clair-impl` / `clair-review` を同梱し、既存の skill インストール
  (`clair-agents` などと同じ仕組み)で `~/.claude/skills` に入れる。中身はユーザーが編集できる。
- リポジトリごとに実装の流儀の skill がある(Clair の `clair-task` は Clair 専用で、ほかでは使えない)。
  そのため、その Project のその列で使う skill がまだ決まっていなければ、起動した列の agent が最初に
  リポジトリの `.claude/skills/` を調べ、「この skill を使う / 使わない」と理由を提案する。
  人が承認したら、Project×列ごとに、選んだ skill と、そのときの skill 一覧を記録する。
- 記録したときと skill 一覧が変わっていたら、次の起動でもう一度調べさせる。
- 起動時のプロンプトには、選んだ skill(または既定の skill)と、Q18 の結果報告の1行の指示を入れる。

### 起動

- 列の agent は Mac 上の対話モードの `claude` で起動する。sandbox(`sbx`)と `claude -p` は使わない
  (動作検証にローカルの環境が要るため)。
- 子の許可プロンプト(Claude Code の「Do you want to proceed?」)には、どこにフォーカスがあっても
  ⌥⌘Y(Yes)/ ⌥⌘N(No)で、いちばん古い入力待ちのカードに答えられる。送った先のカードは一瞬強調する。
  ⌥⌘Y は二段にする。一回目はそのカードの画面の末尾(何を許可するか)を右下に出すだけで、出ている間の二回目で「1」(番号付きの Yes)を送る。
  ⌥⌘N は一回で Esc を送る(拒否は安全側なので確認しない)。
  看板にフォーカスがあるときは、選択中のカードに同じキーで答える。⌘] で次の入力待ちカードへ移る。

## コンシェルジュ(チャット)の役割

- 依頼の意図を自分で判断する。「調べといて」「やっといて」のように実行を頼まれたら、カードを作って
  列に置き、起動まで行う。置く列(Plan か、やることが明確な小さな修正なら Impl)もコンシェルジュが決める。
  Impl に直接置いたカードには、`plan.md` の代わりに依頼文を渡す。
- 「todo に追加して」のように溜めておく意図なら、Inbox に置いて止める。
- 意図がどうしても分からないときと、危険な操作(削除・push・force など)を伴うときは、Inbox に置き、
  進めてよいかをチャットで聞く。
- コンシェルジュが起動する子は、必ず先にカードを作る(看板の外で動く子を作らない)。
  Project 画面で人が手動で起動した agent は、看板の下の「その他のエージェント」の帯に出す。
- コンシェルジュの固定の役割(`Concierge.basePrompt`)の TODO 節と工程の説明を、この節に合わせて書き直す。

## 承認

- `todo.add` / `todo.update` は既定で承認なし。
- 人のドラッグと、コンシェルジュによる列への配置(上の判断に従うもの)で起きる列の agent の起動は、
  承認カードを出さない。コンシェルジュがカードを介さずに `agent.launch` するときだけ、今の設定に従う。
- `todo.update` は承認なしなので、`stage` の変更で起動できる呼び出し元を限る。起動するのは、GUI の操作と、
  `caller` がコンシェルジュの terminal の `todo.update` だけ。子 agent や Clair の外からの `stage` の変更は
  記録だけして起動しない(承認なしの `todo.update` が、承認の要る `agent.launch` の抜け道にならないように)。
- コンシェルジュが読んだ外部の文章に誘導されて起動する(プロンプトインジェクション)ことへの対策として、
  コンシェルジュは `--disallowedTools WebFetch,WebSearch` で起動し、Web とリポジトリの調査は子に任せる。
  承認なしで起動できるのはチャットの依頼1件につき3体までで、超えたら承認カードを出す(依頼1件 = hook の
  `UserPromptSubmit` から `Stop` まで)。子は Claude Code の通常の権限確認つきで動くので、誘導された子の
  書き込みとコマンド実行には ⌥⌘Y が要る。
- 通知は今の仕組みのまま(前面なら Clair 内のカード、背面なら macOS notification)。

## 範囲外

- iOS(`apps/mobile`)には、コンシェルジュ・TODO・看板のどれも実装されていない。今回は触らない。
- 工程の自動遷移(ループ)。

## Dependencies

- Design canvas(`clair-workbench-sync`)に3列・カード・切り替えボタンを先に描く。
- ADR-0028 を accepted にする。ADR-0027 に追記する。
- spec(`docs/clair-spec.md`)のコンシェルジュ・TODO・承認の段落は、各 Slice の実装と同じコミットで書き換える。

## Slice 1: 画面の骨格(3列・切り替えボタン)

- コンシェルジュ画面を3列の分割にし、幅を保存する。チャットを畳めるようにする。
- titlebar 右端の切り替えボタンと ⌃⌘0。起動時は常にコンシェルジュ。
- activity bar のコンシェルジュアイコンと `startConcierge` を削除する。
- 今のタイル領域を削除し、看板を全面に置く(カードの中身は Slice 3)。

## Slice 2: 看板の操作と列の agent

- カードのドラッグ(実行中は確認)、列ごとの起動、Project の選択パレット(「Project なし」を含む)。
- 列の skill の調査・承認・記録と、同梱の `clair-plan` / `clair-impl` / `clair-review`。
- `todo.update` に `result` / `note` を足す。状態の判定。
- Done の後片付け、7 日の表示期間、検索。
- `stage` の読み替え(`submit` / `check-*` / `review` → Review)。
- コンシェルジュの固定の役割と承認の既定値(ADR-0027 の追記)。
- コンシェルジュの `--disallowedTools WebFetch,WebSearch` と、依頼1件あたり3体の承認なし起動の上限。

## Slice 3: カードのライブ画面と承認キー

- 全カードに画面の末尾を出す。一度も表示していない pane も、terminal journal と headless VT で読む。
- 看板の横スクロール、クイックルック。
- ⌥⌘Y / ⌥⌘N、⌘]、送った先の強調。
- 「その他のエージェント」の帯。

## Slice 4: エディタ列

- コンシェルジュ画面のエディタ列(タブのみ)。Project 側とバッファを共有する。
- コンシェルジュ画面にいる間の `file.open` / `clair open` の行き先をエディタ列にする。

## Slice 5: TODO の UI の削除

- サイドバーの TODO パネル(`ClairTodoViews.swift` など)と activity bar の TODO アイコンを削除する。
  `todo.*` コマンド・`clair-todo` skill・保存形式は残す。

Slice 1 が他の Slice の土台になる。Slice 2–5 は Slice 1 の後に並列で進められる
(Slice 3 と 4 は Slice 1 の列の枠だけに依存し、Slice 5 は独立している)。
