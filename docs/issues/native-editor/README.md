## 現時点の結論

CodeEdit系は条件付き候補。実IME未検証、上流複数カーソルUndoにadapterが必要、10MB初回色付け約4.7秒、累積RSS約1.1GiB。本番でVS Code相当との判定は未達。diffは共通2列表と固定提案の検証であり、任意差分の編集機能の完成ではない。測定境界が違うAPI時間から速度比を出さない。

## プロジェクト全体の完了条件

PoCの合格だけでは完了ではない。通常編集・diff・行コメント・AI提案操作が製品の実データ経路に接続され、NE-21のゲートを通り、NE-22の既定切替とNE-23の整理まで完了すること。AIサービスの実送信はユーザー操作を必要とし、fake検証と実送信の証跡を混同しない。実装のリリース作業は別途扱う。

同一Macでの性能計測、実IMEのUI操作、Swift host testは並行実行しない。各agentは独立ブランチ/worktreeを使い、他agentの変更を上書き・resetしない。共有の準備ができたコミットを取り込んで依存を満たす。実行前に既存プロセスを確認し、新しく起動したものだけを終了する。

## 共通の作業ルール

- 一回の担当は一Issue。依存の未完了を推測で埋めない。作業開始時に状態をin_progressへ、合格証跡が揃ってからdoneへ変更する。

- ローカルコミットは成果共有のために作成可能。対象ファイルのみをstageし、既存のユーザー変更を混ぜない。pushや外部への連絡はしない。
