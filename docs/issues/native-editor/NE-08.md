# NE-08: 任意差分の行・hunkモデルを作る

- 状態: open
- 優先度: P1
- 依存: [NE-02](NE-02.md)
- 担当範囲: 新規diffモデルとfixtureテスト
- 作成日: 2026-09-08

## 目的と前提

任意差分の行・hunkモデルを作る。これはネイティブエディタPoCの残作業であり、本番への無条件採用は決定していない。
開始前に[共通ルールと基準](README.md)、[PoC報告](evidence/poc-report.md)を読む。NE-00完了後のソースを基準にし、依存Issueの成果コミットと完了条件を確認してから着手する。

## 実施手順

1. PoC alignedRowsと現行diff parserを読み、old/new文書revisionと論理行対応を保持するモデルを作る。
2. 追加・削除・置換・空ファイル・空行・末尾改行なし・CRLF/LF・Unicodeを扱う。表示用の空欄を本文に挿入しない。
3. 行/hunk IDを文書ペアとrevisionに紐付け、変更前後範囲と対応表を返す。
4. 10000行/2000置換などの負荷で計算時間を測り、バックグラウンド計算・取消・古い結果の破棄を実装する。

## 完了条件・検証

1. fixtureのold/new本文を行対応から復元でき、改行コードと末尾改行が失われない。
2. 同一revisionの再計算でIDが安定し、別revisionのIDを流用しない。
3. rename metadataと本文差分を分離し、binaryは非対応を明示。計算中もUIを塞がない。

## 対象外

Git stage/unstage、editable左右pane、diff UI。

## 引き継ぎ時に記録するもの

- 変更したファイルと成果コミットSHA（共有の指示なしにpushしない）。
- 実行したコマンド、環境、入力fixture、期待結果と実結果、証跡への相対リンク。
- 未検証・既知の制限。実行不能の場合は状態をblockedにし、不足している入力/環境を具体的に書く。
- 完了条件を満たした場合だけdoneに変更する。後続Issueの依存欄に共有可能な成果を追記する。
