# NE-23: 旧native実装と移行用コードを整理する

- 状態: open
- 種別: 本番実装
- 依存: [NE-22](NE-22.md)
- 担当範囲: 未使用コード・テスト・ドキュメント
- 作成日: 2026-09-08

## 目的・着手条件

旧native実装と移行用コードを整理する。調査報告やPoCだけでは完了にならない。Clairの本番コードへ実装し、製品経路で検証する。
[共通ルール](README.md)を読み、依存の成功SHAを含む隔離worktreeで作業する。NE-13の判断が不採用ならCodeEdit依存の本番実装を開始せず、代案を決定する追加Issueを作る。未達ゲートを無視しない。
UI変更は既存のClairデザインを維持する。新規UIが必要な場合は該当design/mock skillに従って先に仕様を確立し、本Issueにリンクする。

## 実施手順

1. 旧ProjectSourceEditorView/正規表現highlighterと新nativeの参照を調査する。NativeEditor.swiftには文書モデルもあるためファイル丸ごと削除しない。
2. 参照ゼロで機能が移行済みの旧ビュー、実験専用コード、不要資産だけを削除する。
3. NE-22で維持するWeb fallbackとそのbuild資産、共通保存/履歴は残す。PoC証跡は履歴として残す。
4. 関連architecture/runbookを現在の構成へ更新し、ビルドと影響するテストを実行する。

## 完了条件・検証

1. 削除対象ごとに移行先または不要の根拠が示され、旧実装への稼働参照がない。
2. native既定とWeb fallbackがともに動く。
3. 配布bundleに不要な旧native資産が残らず、検証手順が現行と一致する。

## 対象外

Web完全撤去、機能縮小、履歴証跡削除。

## 成果の引き継ぎ

変更ファイル、成功コミットSHA、実行コマンド、期待値と実結果、証跡へのリンクを追記する。必須項目が未検証ならdoneにしない。失敗時は再現手順・影響・不足条件を記録する。既存ユーザー変更をstageしない。push/外部公開はしない。
