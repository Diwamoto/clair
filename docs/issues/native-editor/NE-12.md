# NE-12: Clair全体とVS Codeを同条件で測定する

- 状態: open
- 優先度: P0
- 依存: [NE-11](NE-11.md), [NE-14](NE-14.md)
- 担当範囲: 専用性能ハーネス、証跡、集計
- 作成日: 2026-09-08

## 目的と前提

Clair全体とVS Codeを同条件で測定する。これはネイティブエディタPoCの残作業であり、本番への無条件採用は決定していない。
開始前に[共通ルールと基準](README.md)、[PoC報告](evidence/poc-report.md)を読む。NE-00完了後のソースを基準にし、依存Issueの成果コミットと完了条件を確認してから着手する。

## 実施手順

1. PoC API時間は完了境界が異なるため速度比に使わない。実キー→描画、frame time、first visible text/highlight、warm tab、process tree CPU/RSSを別指標に定義する。
2. 同じfixture/hash、本文viewport、font、wrap/minimap、OSでClair Web・Clair native・独立profileのVS Codeを測る。revisionとbuild設定を保存する。
3. cold/warm各5run、反復操作各30回を目安に測り、生データからp50/p95を生成する。異なる2文書でタブ往復する。
4. 通常/1MB/10MB/長行/50タブと実IME・スクロール中入力を確認する。取得不能な指標は未検証にし、API応答時間で置き換えない。

## 完了条件・検証

1. 再現手順、生データ、集計スクリプト、条件表があり、第三者が同じ集計を作れる。
2. ネイティブが現行より改善した点/悪化した点/不明を指標別に記載する。
3. 暫定目標は通常入力p95 16.7ms以内、warmタブp95 100ms以内、対応するVS Code指標比1.2倍以内。達成のために測定後に閾値を緩めない。メモリは同一文書集合で比較する。

## 対象外

公平でないAPI速度比、ユーザーのVS Code設定変更、独立測定の同時実行。

## 引き継ぎ時に記録するもの

- 変更したファイルと成果コミットSHA（共有の指示なしにpushしない）。
- 実行したコマンド、環境、入力fixture、期待結果と実結果、証跡への相対リンク。
- 未検証・既知の制限。実行不能の場合は状態をblockedにし、不足している入力/環境を具体的に書く。
- 完了条件を満たした場合だけdoneに変更する。後続Issueの依存欄に共有可能な成果を追記する。
