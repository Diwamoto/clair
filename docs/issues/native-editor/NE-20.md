# NE-20: 本番AI要求を行・範囲と安全な提案適用へ接続する

- 状態: open
- 種別: 本番実装
- 依存: [NE-10](NE-10.md), [NE-18](NE-18.md), [NE-19](NE-19.md)
- 担当範囲: 既存AI command adapter、提案preview UI
- 作成日: 2026-09-08

## 目的・着手条件

本番AI要求を行・範囲と安全な提案適用へ接続する。調査報告やPoCだけでは完了にならない。Clairの本番コードへ実装し、製品経路で検証する。
[共通ルール](README.md)を読み、依存の成功SHAを含む隔離worktreeで作業する。NE-13の判断が不採用ならCodeEdit依存の本番実装を開始せず、代案を決定する追加Issueを作る。未達ゲートを無視しない。
UI変更は既存のClairデザインを維持する。新規UIが必要な場合は該当design/mock skillに従って先に仕様を確立し、本Issueにリンクする。

## 実施手順

1. 既存AI送信経路/typed commandを調査し、UIの明示操作でproject/worktree/document/revision/範囲と必要contextを渡す。自動送信を追加しない。
2. 応答をNE-10の検証可能な提案モデルに変換する。形式不正や別ファイルを対象とする応答は適用せず表示する。
3. NE-19のdiffで提案をpreviewし、全適用/行・hunk部分適用/却下/Undoを接続する。
4. 処理中の本文変更、外部変更、cancel、失敗、部分適用後の残り再計算を処理する。テストには既存サービス境界のfakeを使用する。

## 完了条件・検証

1. 実際の製品UIからfake providerを通した要求→応答→preview→部分適用→Undoが完走する。
2. 要求後に本文を変えると古い応答が誤適用されない。
3. 既存providerへの接続が実装され、実送信未検証ならその旨を残す。テスト目的の外部送信はユーザーの明示操作に限る。

## 対象外

新規AIサービス契約、無操作での送信、Git自動commit。

## 成果の引き継ぎ

変更ファイル、成功コミットSHA、実行コマンド、期待値と実結果、証跡へのリンクを追記する。必須項目が未検証ならdoneにしない。失敗時は再現手順・影響・不足条件を記録する。既存ユーザー変更をstageしない。push/外部公開はしない。
