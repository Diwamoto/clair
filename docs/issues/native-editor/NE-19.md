# NE-19: Git・履歴のdiff表示を本番ネイティブビューへ接続する

- 状態: open
- 種別: 本番実装
- 依存: [NE-09](NE-09.md), [NE-15](NE-15.md), [NE-16](NE-16.md)
- 担当範囲: Git/履歴diff adapter、diffタブ保存復元
- 作成日: 2026-09-08

## 目的・着手条件

Git・履歴のdiff表示を本番ネイティブビューへ接続する。調査報告やPoCだけでは完了にならない。Clairの本番コードへ実装し、製品経路で検証する。
[共通ルール](README.md)を読み、依存の成功SHAを含む隔離worktreeで作業する。NE-13の判断が不採用ならCodeEdit依存の本番実装を開始せず、代案を決定する追加Issueを作る。未達ゲートを無視しない。
UI変更は既存のClairデザインを維持する。新規UIが必要な場合は該当design/mock skillに従って先に仕様を確立し、本Issueにリンクする。

## 実施手順

1. 現行Git/履歴diffの入口と比較元を調査し、HEAD/index/working tree/履歴snapshotのどの2つを比較するか明示的なdescriptorにする。
2. NE-08/09へ実データを渡し、unified/左右切替、行番号、ハイライト、rename/new/deleted/binary状態を表示する。
3. diffタブの比較descriptorと表示位置を既存のworkspace保存へ接続する。再起動時に別ファイルや別revisionを開かない。
4. 読取専用の実験設定で既存表示と切替可能にする。比較元が消えた場合はmissingとして再選択させる。

## 完了条件・検証

1. 実Git repositoryの追加/削除/rename/CRLF/末尾改行なしと履歴比較で正しい内容が出る。
2. diffタブを閉じて再開、アプリ再起動しても比較対象が一致する。
3. 大diff・幅変更・折返しの本番表示を確認し、固定サンプルに依存しない。

## 対象外

stage/unstageの新規実装、編集可能な左右pane。

## 成果の引き継ぎ

変更ファイル、成功コミットSHA、実行コマンド、期待値と実結果、証跡へのリンクを追記する。必須項目が未検証ならdoneにしない。失敗時は再現手順・影響・不足条件を記録する。既存ユーザー変更をstageしない。push/外部公開はしない。
