# NE-05: メモリ保持を調べてタブ解放・大規模ファイル方針を作る

- 状態: open
- 優先度: P1
- 依存: [NE-00](NE-00.md)
- 担当範囲: PoC文書lifecycle、メモリ計測
- 作成日: 2026-09-08

## 目的と前提

メモリ保持を調べてタブ解放・大規模ファイル方針を作る。これはネイティブエディタPoCの残作業であり、本番への無条件採用は決定していない。
開始前に[共通ルールと基準](README.md)、[PoC報告](evidence/poc-report.md)を読む。NE-00完了後のソースを基準にし、依存Issueの成果コミットと完了条件を確認してから着手する。

## 実施手順

1. PoC累積RSS約1.1GiBを再現し、単独ファイルの新規プロセス測定と複数ファイル保持測定を分ける。
2. 通常/1MB/10MB/長行/50タブでprocess footprintとRSSを採り、close後のcontroller・parser・delegate・viewの解放を検証する。
3. 不要な参照や解析ジョブを解放する。非表示文書の表示キャッシュ解放と、dirty本文/Undoを守る方針を実装する。
4. ファイルbyte数、UTF-16長、最大行長に基づくnative対象範囲とfallback条件を記録する。大きいファイルで既存Webが安全と仮定しない。

## 完了条件・検証

1. 各fixture単独/累積/close後の測定値と計測時刻がある。
2. closeした文書の解放をテストし、再オープンやタブ復帰で本文・選択・Undoが仕様通り保たれる。
3. fallback/制限表示の条件を数値で記述し、その境界のテストがある。

## 対象外

dirtyタブやUndoの無断破棄、ユーザー文書での破壊的負荷試験。

## 引き継ぎ時に記録するもの

- 変更したファイルと成果コミットSHA（共有の指示なしにpushしない）。
- 実行したコマンド、環境、入力fixture、期待結果と実結果、証跡への相対リンク。
- 未検証・既知の制限。実行不能の場合は状態をblockedにし、不足している入力/環境を具体的に書く。
- 完了条件を満たした場合だけdoneに変更する。後続Issueの依存欄に共有可能な成果を追記する。
