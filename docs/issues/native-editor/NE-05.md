# NE-05: メモリ保持を調べてタブ解放・大規模ファイル方針を作る

- 状態: open
- 優先度: P1
- 依存: [NE-00](NE-00.md)
- 担当範囲: PoC文書lifecycle、メモリ計測
- 作成日: 2026-09-08

## 部分完了記録（2026-09-08）

- `prototypes/native-editor-poc/Sources/NativeEditorPoC/Document.swift` に、clean tabだけの表示cache解放、本文・selection・scroll snapshot、dirty/Undo/composition/proposal保持、再オープン復元を追加した。
- `LifecyclePolicy.swift` にUTF-8 bytes `10,000,000`、UTF-16長 `10,000,000`、最大行UTF-16長 `1,000,000`、同期解析 `250,000` UTF-16の数値境界を追加した。
- self-testで `clean tab releases display cache`、`reopen preserves text and selection`、`dirty tab retains undo-capable display`、`retained tab undo restores body` と各境界テストがPASSした。上流の複数カーソルUndo expected failureは従来どおり除外される。
- fixture単独/累積/close後の値は [NE-05 lifecycle evidence](evidence/ne05-lifecycle.md) に記録した。個別probeは `python3 make-fixtures.py`、`python3 prepare-build.py`、`swift build -c release --package-path prototypes/native-editor-poc`、`python3 package-app.py`、`NativeEditorPoC --lifecycle-probe -ApplePersistenceIgnoreState YES fixtures/<fixture>` で実行した。
- 10MBではclose APIがtrueでもclose後footprintが増え、非同期Tree-sitter parse/query jobのcancelとidle確認が未解決である。このため完了条件1/2を全面達成したとみなさず、状態は `open` のままとする。10MBと最大行超過はnativeへ無条件投入せずfallback候補とする。

## 目的と前提

メモリ保持を調べてタブ解放・大規模ファイル方針を作る。これはネイティブエディタPoCの残作業であり、本番への無条件採用は決定していない。
開始前に[共通ルールと基準](README.md)、[PoC報告](evidence/poc-report.md)を読む。NE-00完了後のソースを基準にし、依存Issueの成果コミットと完了条件を確認してから着手する。

## 実施手順

1. PoC累積RSS約1.1GiBを再現し、単独ファイルの新規プロセス測定と複数ファイル保持測定を分ける。
2. 通常/1MB/10MB/長行/50タブでprocess footprintとRSSを採り、close後のcontroller・parser・delegate・viewの解放を検証する。
3. 不要な参照や解析ジョブを解放する。非表示文書の表示キャッシュ解放と、dirty本文/Undoを守る方針を実装する。
4. ファイルbyte数、UTF-16長、最大行長に基づくnative対象範囲とfallback条件を記録する。大きいファイルで既存Webが安全と仮定しない。

## 完了条件・検証

1. 各fixture単独/累積/close後の測定値と計測時刻がある。
2. closeした文書の解放をテストし、再オープンやタブ復帰で本文・選択・Undoが仕様通り保たれる。
3. fallback/制限表示の条件を数値で記述し、その境界のテストがある。

## 対象外

dirtyタブやUndoの無断破棄、ユーザー文書での破壊的負荷試験。
