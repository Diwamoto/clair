# NE-02: 文書の差分更新・revision契約を実装する

- 状態: open
- 優先度: P0
- 依存: [NE-00](NE-00.md)
- 担当範囲: 新規エンジン非依存文書モデルと単体テスト
- 作成日: 2026-09-08

## 目的と前提

文書の差分更新・revision契約を実装する。これはネイティブエディタPoCの残作業であり、本番への無条件採用は決定していない。
開始前に[共通ルールと基準](README.md)、[PoC報告](evidence/poc-report.md)を読む。NE-00完了後のソースを基準にし、依存Issueの成果コミットと完了条件を確認してから着手する。

## 実施手順

1. 既存ProjectEditorTabの保存・dirty・外部変更・履歴・selection利用箇所を列挙する。
2. UTF-16範囲、置換文字列、基準revision、編集元、Undo単位を持つtransactionを定義する。複数編集の座標が編集前基準か逐次基準かを一つに固定する。
3. 範囲不正、古いrevision、Unicodeの不正境界を拒否し、transactionを原子的に適用する。選択通知は本文更新と分離する。
4. 初回ロード/保存/明示的diff生成に使うsnapshot APIと、変更範囲通知を実装する。公開Stringを毎入力で更新する設計を導入しない。

## 完了条件・検証

1. 挿入・削除・複数範囲・emoji・結合文字・古いrevision・不正範囲のテストが通る。
2. 選択変更でrevisionも本文snapshot取得回数も増えない。
3. 既存保存機能へ繋ぐ対応表とAPI利用例があり、後続が契約を推測せず使える。

## 対象外

画面全体の改修、実AI接続、保存処理の全面置換。

## 引き継ぎ時に記録するもの

- 変更したファイルと成果コミットSHA（共有の指示なしにpushしない）。
- 実行したコマンド、環境、入力fixture、期待結果と実結果、証跡への相対リンク。
- 未検証・既知の制限。実行不能の場合は状態をblockedにし、不足している入力/環境を具体的に書く。
- 完了条件を満たした場合だけdoneに変更する。後続Issueの依存欄に共有可能な成果を追記する。
