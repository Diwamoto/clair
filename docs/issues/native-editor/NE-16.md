# NE-16: 本番の保存・外部更新・履歴を差分文書へ移行する

- 状態: open
- 種別: 本番実装
- 依存: [NE-11](NE-11.md), [NE-15](NE-15.md)
- 担当範囲: ProjectEditorTab、文書lifecycle、保存/履歴テスト
- 作成日: 2026-09-08

## 目的・着手条件

本番の保存・外部更新・履歴を差分文書へ移行する。調査報告やPoCだけでは完了にならない。Clairの本番コードへ実装し、製品経路で検証する。
[共通ルール](README.md)を読み、依存の成功SHAを含む隔離worktreeで作業する。NE-13の判断が不採用ならCodeEdit依存の本番実装を開始せず、代案を決定する追加Issueを作る。未達ゲートを無視しない。
UI変更は既存のClairデザインを維持する。新規UIが必要な場合は該当design/mock skillに従って先に仕様を確立し、本Issueにリンクする。

## 実施手順

1. NE-11の暫定接続と全content参照を調べ、常時全文Published更新が残る利用箇所を一覧にする。
2. dirty、保存、保存失敗、外部変更、missing/read-only、ローカル履歴をNE-02のrevision/snapshotへ接続する。保存中の後続編集を保存済みと誤認しない。
3. 外部更新と未保存編集の競合で既存の保護動作を維持する。reloadでUndoを維持/破棄する条件を明記する。
4. 履歴作成は保存や既存の履歴ポリシーに従い、毎キーsnapshotを作らない。既存テストを移行し回帰検証する。

## 完了条件・検証

1. 保存中の編集、保存権限エラー、外部削除/再作成、外部更新との競合をテストしデータを失わない。
2. dirtyは最後に保存されたrevisionと一致し、履歴復元後の本文を保存・Undoできる。
3. 通常入力/選択の経路に全文snapshot取得がないことを計測またはspyで確認する。

## 対象外

履歴機能の新仕様、外部ファイルの無断上書き。

## 成果の引き継ぎ

変更ファイル、成功コミットSHA、実行コマンド、期待値と実結果、証跡へのリンクを追記する。必須項目が未検証ならdoneにしない。失敗時は再現手順・影響・不足条件を記録する。既存ユーザー変更をstageしない。push/外部公開はしない。
