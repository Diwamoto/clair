# NE-04: 初回ハイライトと解析スケジューリングを改善する

- 状態: done
- 優先度: P1
- 依存: [NE-00](NE-00.md)
- 担当範囲: PoCハイライト初期化・解析設定
- 作成日: 2026-09-08

## 目的と前提

初回ハイライトと解析スケジューリングを改善する。これはネイティブエディタPoCの残作業であり、本番への無条件採用は決定していない。
開始前に[共通ルールと基準](README.md)、[PoC報告](evidence/poc-report.md)を読む。NE-00完了後のソースを基準にし、依存Issueの成果コミットと完了条件を確認してから着手する。

## 実施手順

1. 空view配置後setText、初回可視範囲通知、query資産配置の回避策を再現し、それぞれの必要理由を記録する。
2. 同期閾値250000 UTF-16を出発点に、通常/1MB/10MB/1MB長行の初回色付けと編集中の応答を測定する。
3. 解析中に連続編集・タブ切替を行い、古いrevisionの色が後から上書きされないよう処理を整理する。
4. Swift複数行文字列、Rustネストコメント、TSX、Markdown内Swiftについて編集後の正しいtoken色を検証する。入力を軽くするためにハイライトを黙って停止しない。

## 完了条件・検証

1. 全6言語のqueryとtoken色テストが通り、編集後も色が更新される。
2. 同じfixture/計測境界で変更前後の初回色付け・入力p50/p95を記録する。
3. 採用する閾値と根拠を記載。改善不能な10MB/長行は制限とfallback条件を明示し、VS Code同等と主張しない。

## 対象外

semantic token/LSP実装、計測値を描画遅延と呼ぶこと。

## 引き継ぎ時に記録するもの

- 変更したファイルと成果コミットSHA（共有の指示なしにpushしない）。
- 実行したコマンド、環境、入力fixture、期待結果と実結果、証跡への相対リンク。
- 未検証・既知の制限。実行不能の場合は状態をblockedにし、不足している入力/環境を具体的に書く。
- 完了条件を満たした場合だけdoneに変更する。後続Issueの依存欄に共有可能な成果を追記する。

## 完了記録（2026-09-08）

- `prototypes/native-editor-poc/Sources/NativeEditorPoC/HighlightScheduling.swift` に revision gate 付き `HighlightProviding` adapter を追加した。解析・query callback は開始時 revision と一致しない場合に `operationCancelled` として返し、`Highlighter` の再キュー経路へ戻す。連続編集・タブ切替で古い色が後から適用される境界を作らない。
- 初回ロードは空の `TextViewController` を view に配置し、実 frame 確定後に `setText`、同期 layout と bounds 通知を一度行う。次の main-queue turn では bounds 通知だけを再送し、長行全体の layout を二重に強制しない。query 資産は既存 `prepare-build.py` の bundle 配置を維持する。
- 既定の `TreeSitterClient.Constants.maxSyncContentLength` を 250,000 UTF-16 に変更した。`--legacy-policy` で旧 1,000,000 UTF-16 境界を再現でき、既存 `--async-policy` は後方互換のまま既定値を使用する。
- self-test: `./run.sh --self-test --ne04` は終了コード0。上流の複数カーソル1回Undoだけは既存の `expectedFailure`。6言語すべてで query asset、初回 token 色、編集後 token 色の更新を確認し、revision gate の stale/current 判定も PASS。
- 測定: `./run.sh --benchmark --ne04` を同一 fixture・画面・API境界で単独実行。生データは [`benchmark-ne04.json`](../../../prototypes/native-editor-poc/evidence/benchmark-ne04.json)、ログは [`benchmark-ne04.log`](../../../prototypes/native-editor-poc/evidence/benchmark-ne04.log)、集計は [`MEASUREMENTS.md`](../../../prototypes/native-editor-poc/MEASUREMENTS.md)。10MB の入力 p50/p95 は 3.41/3.70ms、1MB は 3.77/3.92ms。1MB長行は初回可視色付け約3.0秒、入力684.86/693.29msとして制限を確認した。
- 採用方針: 250,000 UTF-16 超は非同期解析を維持し、ハイライトを黙って停止しない。10MB と長行の性能・累積RSSは本番既定採用の根拠にせず、NE-05/NE-11 で既存エディタ fallback 条件（UTF-16長・長行・解析負荷）を接続する。VS Code 同等とは主張しない。
- 依存 NE-00 の共有 PoC と固定 `Package.resolved` を変更していない。SwiftPM/Release build は成功（依存側の既知の絶対パス warning のみ）。全ソース lint は既存 PoC の大量違反があるため不合格で、今回の差分だけを原因とする新規 build failure はない。
