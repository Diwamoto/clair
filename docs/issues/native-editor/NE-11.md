### Dev-only adapter接続（2026-09-09）

依存ゲートを閉じたまま実機で接続を試せるよう、`ProjectSourceEditorView` をClair Dev限定で明示opt-inする。Stableはコンパイル時に常にfalseで、通常のDev起動もCodeMirrorのままにする。

```sh
defaults write com.diwamoto.clair.dev clair.editor.native-v1 -bool true
```

上記を設定してClair Devを再起動すると、通常エディタだけがAppKit adapterになり、Command-S、dirty、read-only/missing、外部変更、Unicode/IME、Undo、検索ジャンプ、タブごとの選択・スクロール保存を同じ `ProjectEditorTab` 経路で試せる。`defaults delete com.diwamoto.clair.dev clair.editor.native-v1` で既定のCodeMirror経路に戻る。CodeEdit/Tree-sitterの本番接続、diff置換、配布依存の解消を意味しない。

## 目的と前提

通常エディタを本番ホストへopt-inで接続する。これはネイティブエディタPoCの残作業であり、本番への無条件採用は決定していない。
開始前に[共通ルールと基準](README.md)、[PoC報告](evidence/poc-report.md)を読む。NE-00完了後のソースを基準にし、依存Issueの成果コミットと完了条件を確認してから着手する。

## 実施手順

1. 依存Issueの成功SHAを取り込み、既存Web/native利用箇所と現在の未コミット作業との差分を確認する。
2. ユーザーが明示選択できる実験的native経路を追加し、既定は維持する。Issue02の文書契約に接続する。
3. 保存/Command-S、dirty、read-only、missing、外部変更検知、保存失敗、ローカル履歴、検索結果への移動を維持する。
4. タブごとにUndo/選択/スクロールを保持する。エンジン切替はIME終了と未保存本文保護を行い、変更を失う切替は拒否する。
5. 大規模fileの制限をIssue05に従って適用し、必要なSwiftテストをmake test-swiftで一回ずつ実行する。

## 完了条件・検証

1. 既存保存/外部変更/履歴テストと新adapterテストが通る。
2. 未保存編集を含む複数タブの往復、再読込、エンジン切替でデータ損失がない。
3. ライセンス未解決なら本Issueはblocked。通常版・diffの既定経路を変更しない。

## 対象外

既定native化、公開/配布、diffの置換。
