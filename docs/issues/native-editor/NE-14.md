# NE-14: Web側の全文通知を減らしタブ状態を保持する

- 状態: done
- 優先度: P1
- 依存: [NE-00](NE-00.md)、[NE-02](NE-02.md)
- 担当範囲: editor-web/src/main.ts、native bridge、CodeMirrorEditor.swift
- 作成日: 2026-09-08

## 目的

移行中に残すWebエディタの全文転送を減らし、安全な比較対象を維持する。既存の未コミット変更にはstate cacheの実装がある可能性があるため、旧PoC報告だけで未実装と決めつけない。

## 実施手順

1. 共通READMEと現行ソースを読み、現在のstate cache・選択通知・本文通知を確認する。NE-02のrevision/transaction契約を使う。
2. 選択通知から本文を外す。本文編集は変更範囲と基準revisionを送り、Swiftで全文の再Published更新を行わない。初回/保存/明示的再同期のsnapshot経路は残す。
3. 文書別EditorStateと選択・スクロール・Undoを保持し、タブ切替で不要な再生成を避ける。文書close時にcacheを解放する。
4. 通知の順序、古いrevision、再ロード、IME中の通知、save直前の未反映編集を確認する。不整合時は明示的再同期を行い、内容を黙って捨てない。
5. 既存のbundle生成手順で資産を再生成し、ソースと配布資産のhashを記録する。diff用bridgeを壊さない。

## 完了条件・検証

- 10MB文書の20回の選択移動で本文の転送byteが0。選択とUndo状態は正しく届く。
- 連続編集・貼付・複数範囲変更でnativeモデルとWeb本文が一致し、保存ファイルにも直前の編集が含まれる。
- 2つの異なる文書のタブ往復でUndo、カーソル、スクロールが保持され、外部再読込も反映する。
- 通知欠落/古いrevisionの回帰テストと、変更前後の転送量が残る。API時間を最終描画時間と呼ばない。
- 本文変更とselection変更を分離したbridgeの仕様、成果SHA、検証コマンドと証跡を本Issueへ追記する。

## 対象外

native既定化、diffの全面改修、他agentの未コミット変更の破棄、push/公開。

## 統合上の注意

NE-11と本番adapter周辺で競合するため、別worktreeで実装し統合は順番に行う。NE-12ではこの修正版と、PoCで凍結した旧Webのどちらを比較したか明記する。旧Webだけを比較してnative採用の根拠にしない。

## 実装記録（2026-09-08）

- [ProjectEditorWebBridge.swift](../../../apple/ClairApp/ProjectEditorWebBridge.swift) に、CodeMirrorのUTF-16 `from`/`to`/`insert`、`baseRevision`、選択、Undo状態を表すbridge契約を追加した。selection-onlyイベントは本文フィールドを持たず、revisionも進めない。
- [ProjectEditorDocument.swift](../../../apple/ClairApp/ProjectEditorDocument.swift) のrevision付き文書モデルを [NativeEditor.swift](../../../apple/ClairApp/NativeEditor.swift) の実体に接続した。nativeは範囲transactionを原子的に適用し、stale/不正transactionは本文を変更せず、[CodeMirrorEditor.swift](../../../apple/ClairApp/CodeMirrorEditor.swift) から現在のsnapshotを明示再送する。
- `editor-web/src/main.ts` は本文変更時だけ変更範囲を通知し、選択移動は `{type:"selection", selection, canUndo, canRedo}` のみを通知する。文書別 `EditorState` cacheにrevisionを持たせ、別revisionの外部再読込では古いUndo履歴を再利用しない。WebView破棄時には `releaseDocument` でcacheを解放する。
- cacheの切替時に前文書のrevisionを次文書のrevisionで上書きしないよう、退避→revision更新の順序を固定した。diff用HTML/bridgeは同じbundle生成で維持した。
