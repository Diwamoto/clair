# NE-13: diff操作とコメントを統合して採用判定を残す

- 作成日: 2026-09-08

## 目的と前提

diff操作とコメントを統合して採用判定を残す。これはネイティブエディタPoCの残作業であり、本番への無条件採用は決定していない。
開始前に[共通ルールと基準](README.md)、[PoC報告](evidence/poc-report.md)を読む。NE-00完了後のソースを基準にし、依存Issueの成果コミットと完了条件を確認してから着手する。

## 実施手順

1. 成功した各IssueのSHAを取り込み、差分行/hunk操作から提案適用・コメント作成へ接続する。
2. 行選択→コメント→本文編集→追従→提案の部分適用→残り再計算→Undoを一連で確認する。
3. 通常/diff双方の大fixture、IME、readonly、stale拒否の回帰検証を行い、性能は最終ソースで必要分を再測定する。
4. 採用/条件付き採用/不採用をADR案に記録する。通常エディタとdiffを別判定とし、既定切替条件と戻し方を明記する。

## 完了条件・検証

1. 機能ごとの合格/失敗/未検証、根拠、ソースSHA、制限が一覧になっている。
2. Issue01の配布根拠、03の実IME、12の性能目標が未達なら無条件採用にしない。
3. 残る問題は再現手順とゴール付きの追加Issueにし、本番既定切替は別タスクとして明確に切り離す。

## 対象外

本番既定切替、push/リリース、検証不足のまま全Issueをclose。

## 引き継ぎ時に記録するもの

- 変更したファイルと成果コミットSHA（共有の指示なしにpushしない）。
- 実行したコマンド、環境、入力fixture、期待結果と実結果、証跡への相対リンク。
- 未検証・既知の制限。実行不能の場合は状態をblockedにし、不足している入力/環境を具体的に書く。
- 完了条件を満たした場合だけdoneに変更する。後続Issueの依存欄に共有可能な成果を追記する。
