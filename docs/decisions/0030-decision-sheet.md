# ADR-0030: 判断シート

## Context

ADR-0028 の看板では、Plan の agent が `plan.md` を書き、人がそれを読んで次の列へ移していた。オーナーは
`plan.md` を読んで判断するのが面倒で、どうせ都度コンシェルジュとチャットする(2026-11-18)。人と決めることと、
impl に渡す手順書は別物として扱いたい。判断は質問形式でまとめて、視覚的に(HTML のプレビューで)決めたい。

## Decision

- **判断シート**: agent はユーザーに決めてほしいことを、チャットやペインの文章ではなく判断シートで聞く。
  シートは質問の並びで、各質問は文脈・選択肢・推奨(と理由)を持ち、選択肢ごとに HTML のプレビューを添えられる。
  単一選択・複数選択・自由記述と、シート全体へのコメント欄がある。Clair がネイティブに描き(見た目を統一し、
  回答を構造化する)、HTML は既存の HTML プレビューと同じ制限の WebView で選択肢の中に出す。
- 最初の質問は「この方式で進めてよいか」(agent が決めた方式と、退けた代替案)にする。決める必要のないことは聞かない。
- シートはカードに付く。コンシェルジュもカードの無い質問はまず inbox にカードを作って付ける(チャットに付けない)。回答待ちのカードは
  「あなた待ち」として看板に出し、クリックするとコンシェルジュ画面のエディタ列にシートのタブが開く。
  1 枚のシートに全部の質問をまとめ、「まとめて回答」で一度に返す。
- 回答は Clair が質問した agent のペインに `agent.send` と同じ経路で入力する(agent は長く待ち続けない。
  質問を出したら `blocked` を報告してターンを終える)。質問と回答はカードのフォルダの `decisions.md` に残る。
- **plan.md は impl 専用**。人は読まなくてよい。Plan の agent は必要なら自分で調べ(research を待たない)、
  判断シートで聞き、回答を織り込んで `plan.md` を書く。
- **自動進行**(ADR-0028 の「次の列へ移すのは人」を改める): Plan が `result=ok` を報告し未回答のシートが
  無ければ Clair がカードを Impl に移し、Impl が `result=ok` なら Review に移す。Review の後に Done へ
  移すのは人。`result=failed` か未回答のシートがあれば止まる。
- 質問できるのはすべての agent(コンシェルジュ・research・plan・impl・review)。コンシェルジュの固定の役割と
  同梱の列の skill を「確認はシートで聞く」に書き換える。

## Consequences

- 人の操作は「依頼する」「シートに答える」「Review を見て Done にする」の 3 つになる。
- 新しい command `ask.post`(AI 可、write 未満): シートの JSON を受け取り、カードに付けて表示する。回答の
  入力は GUI からだけ(AI 不可)。HTML の path はカードのフォルダの中に限る。
- 自動進行で agent が続けて起動するので、起動上限(依頼 1 件につき 3 体)の数え方に自動進行を含めない。
- Design canvas にシートのタブと「あなた待ち」のカードを先に描く。

## Addendum (2026-11-18)

- シートはエディタ列のタブではなく、ウィンドウ右下の幅 420pt の浮遊パネルで開く(背景は操作できたまま、× / Esc で閉じる)。
  「まとめて回答」で回答できたら自動で閉じる(owner)。Design canvas の DecisionSheet は後で合わせる。
- 選択式の質問にはそれぞれ任意の補足欄を付け、選択肢と一緒に agent へ返す(`ask.answer` の `notes`、owner)。

## Addendum (2026-11-26)

- [ADR-0032](0032-one-agent-per-card.md) で工程が無くなり、自動進行と plan.md は廃止した。判断シートはそのまま使い、
  質問できるのはそのカードの agent だけになった。
