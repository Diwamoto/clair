# ADR-0029: コンシェルジュを CLI で出す

## Context

ADR-0020 / ADR-0028 はコンシェルジュの本体を raw PTY の Claude Code とし、GUI はその transcript をチャットとして
描画して送信欄の文字を PTY に書き込んでいた。オーナーが使うと、チャットは Claude Code を直接使うより使い勝手が
悪かった(承認や質問のたびにターミナルが重なる、スラッシュコマンドや入力補完が無い、表示が遅れる)。
2026-11-17 にオーナーが「一旦 CLI にする。チャット UI は実験的機能として残す」と決めた。

## Decision

- コンシェルジュ画面の左の列は、コンシェルジュの Claude Code のターミナルそのものを出す。各ペインが 1 つの会話
  (1 つのコンシェルジュ)で、IDE のペインと同じ操作で分割・移動する(⌘D / ⌘⇧D で分割して新しい会話を起動、
  ⌘W で閉じる、パレットのフォーカス移動、⌃⌘M で最大化、⌃⌘= と境界のダブルクリックで均等化、境界のドラッグ、
  ヘッダーのドラッグで入れ替え)。
- 起動の仕組み・承認(#76 の fingerprint)・起動上限・看板・エディタ列・一時ターミナルは変えない。起動上限の
  数え直しは、送信欄の送信の代わりにオーナーがそのターミナルで押した Return で行う(GUI からの入力やほかの
  agent の `agent.send` は数えない)。
- チャットは設定 `conciergeChatUI`(既定オフ、「実験的」)で戻せる。

## Consequences

- Claude Code の機能(スラッシュコマンド、承認、`/resume`)がそのまま使える。会話の一覧と履歴は当初 CLI では
  出さなかったが、2026-11-18 オーナー依頼で左端の縦レールとして戻した(選ぶとフォーカス中のペインの会話を差し替える)。
- ペインの並びは GUI のメモリにだけ持つ。Clair を再起動すると、動いているコンシェルジュ、無ければ最新の会話 1 つを
  開き直す。
- Design canvas はチャットを描いている。CLI の列は IDE のペインの見た目をそのまま使う。
